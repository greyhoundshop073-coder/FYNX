# FYNX Master Execution Checklist

## Operating rule

Work sequentially on `main` in coherent batches. Never start the next batch until the current commit's GitHub Actions workflow is GREEN.

- RED: inspect the exact failing job/log, trace the root cause, fix all directly related issues, push one coherent fix, then re-run CI.
- GREEN: verify the commit and immediately continue with the next unchecked batch.
- Never guess from a red headline; inspect the failing command and surrounding implementation.
- Do not redesign or duplicate existing working systems.
- Use real backend/database/API data; no fabricated production data.
- Preserve existing stronger implementations.
- Keep secrets out of the APK.
- Every pushed batch must have a clear commit message and SHA recorded.

## CI-driven sequence

For every unchecked batch:

1. Inspect current `main` and existing implementation.
2. Investigate dependencies and likely failure points before editing.
3. Implement the complete coherent batch.
4. Commit/push the batch.
5. Read the resulting GitHub Actions run.
6. If RED, inspect exact failed step/log and fix the root cause before any next batch.
7. If GREEN, mark the batch complete and continue.

The assistant must not require the user to report RED/GREEN status manually when GitHub status is accessible.
